# 项目风险：自动返工流程的当前问题与改进建议

## 背景

当前系统已经支持 `auto_rework=true` 自动返工流程。QA 发现问题后，会根据错误类型把任务打回到 `CollectorAgent`、`AnalystAgent` 或 `ReportWriterAgent`，并重新执行后续链路，直到 QA 通过或达到 `max_rework=3` 后进入人工复核。

这个机制已经能展示多 Agent 的 QA 闭环，但当前实现仍然是“Agent 粒度返工”，还不是“精确问题驱动返工”。

## 当前返工流程

当前自动返工大致流程如下：

```text
CollectorAgent
-> AnalystAgent
-> ReportWriterAgent
-> QaAgent

如果 QA failed：
  - missing evidence -> CollectorAgent
  - invalid extraction / contradiction -> AnalystAgent
  - bad report format / missing claim -> ReportWriterAgent

如果 auto_rework=true：
  - 自动重跑对应 Agent 以及后续 Agent
  - 每一轮生成 Trace
  - 最多返工 3 次
  - 超过后进入 manual_review
```

## 已具备的能力

1. QA 能判断不同类型错误并路由到对应 Agent。
2. 自动返工不会导致 workflow 崩溃。
3. 每轮返工都会生成 TraceRecord，方便查看执行过程。
4. `rework_count` 和 `rework_history` 可以展示返工次数和路由路径。
5. 达到 `max_rework=3` 后会进入 `manual_review`，避免无限循环。

## 主要风险

### 1. QA 没有把“缺什么”结构化传给下游 Agent

当前 QA 会返回：

```text
route_to = CollectorAgent / AnalystAgent / ReportWriterAgent
error_type
reason
suggested_action
rework_count
```

但 CollectorAgent、AnalystAgent、ReportWriterAgent 并没有拿到更细的结构化返工信息，例如：

```json
{
  "missing_competitors": ["和平精英"],
  "missing_topics": ["pricing"],
  "failed_claim_ids": ["claim_001"],
  "suggested_queries": [
    "和平精英 官网 定价 充值 会员",
    "和平精英 商业模式 付费 道具"
  ]
}
```

因此当前返工更像是“重新跑一遍相关 Agent”，而不是“针对具体缺口精确补采或重写”。

### 2. 第二次成功可能带有偶然性

如果第一次报告失败，第二次自动返工后成功，可能有以下原因：

1. 搜索 API 返回结果有波动，第二次刚好搜到更相关的 Evidence。
2. LLM ReportWriter 输出有随机性，第二次刚好补齐了缺失竞品或 Claim。
3. 第一次失败点其实不是 Evidence 缺失，而是 ReportWriter 没有覆盖某个竞品，重写报告后刚好通过。
4. Collector 重跑时 query 没有针对 QA 缺口优化，只是重复了原有搜索逻辑。

这意味着当前自动返工可以提升通过率，但还不能完全证明系统具备稳定、可解释的自我修复能力。

### 3. CollectorAgent 没有针对缺失竞品或缺失主题定向补采

例如用户输入：

```text
王者荣耀、和平精英
```

如果 QA 发现“和平精英缺少定价/商业模式相关 Evidence”，理想情况下 CollectorAgent 应该优先补采：

```text
和平精英 官网 充值 付费 道具
和平精英 商业模式 皮肤 赛季通行证
和平精英 revenue monetization in-app purchase
```

但当前 CollectorAgent 仍主要根据原始 task 信息生成 query，并不会根据 QA 的 `missing_topics` 动态调整搜索策略。

### 4. AnalystAgent 返工缺少字段级修复目标

当前 QA 可以把 invalid extraction 打回 AnalystAgent，但没有明确告诉 AnalystAgent：

```json
{
  "failed_schema": "PricingModel",
  "empty_fields": ["tiers", "pricing_notes"],
  "unsupported_fields": ["positioning"],
  "required_evidence_ids": ["ev_xxx", "ev_yyy"]
}
```

这会导致 AnalystAgent 返工时仍然只是重新抽取一遍，而不是针对空字段、冲突字段或无证据字段进行修复。

### 5. ReportWriterAgent 返工缺少 Claim 级别约束

当前 QA 可以发现：

- 某个 Claim 缺少 evidence_ids
- 某个 competitor 没有 Claim
- Claim 使用了其他 competitor 的 Evidence

但返工时 ReportWriterAgent 还没有强制接收结构化修复目标，例如：

```json
{
  "missing_claim_competitors": ["和平精英"],
  "mismatched_evidence_claims": [
    {
      "claim_id": "claim_003",
      "claim_competitor": "和平精英",
      "evidence_competitor": "王者荣耀"
    }
  ]
}
```

因此 LLM 或 Mock Writer 第二次生成成功，仍可能部分依赖 Prompt 和模型随机性。

## 对演示的影响

当前版本仍然适合现场演示，因为它已经能展示：

- 多 Agent DAG
- Schema 校验
- Evidence 绑定
- QA 打回
- 自动返工
- Trace 可观测性
- `max_rework` 人工兜底

但如果评委追问“返工时 Agent 是否知道具体缺什么”，需要明确说明：

> 当前 Demo 已经实现 Agent 级自动返工，但结构化返工指令仍是下一阶段优化点。后续会把 QA 的诊断结果转成 ReworkContext，传给对应 Agent，实现缺口驱动的定向补采、重抽取和重写报告。

## 改进建议

### 高优先级：增加 ReworkContext Schema

建议新增统一结构：

```python
class ReworkContext(BaseModel):
    error_type: str
    route_to: str
    missing_competitors: list[str] = []
    missing_topics: list[str] = []
    failed_claim_ids: list[str] = []
    failed_schema: str | None = None
    mismatched_evidence_claims: list[dict] = []
    suggested_queries: list[str] = []
    suggested_action: str
```

然后在 `QaOutput` 或 `QaResult` 中保存该结构，并在 auto_rework 时传给对应 Agent。

### 高优先级：CollectorAgent 支持定向补采

当 `route_to=CollectorAgent` 时，CollectorAgent 应该读取：

- `missing_competitors`
- `missing_topics`
- `suggested_queries`

并优先执行这些 query，而不是重复原始 query。

示例：

```text
missing_competitors = ["和平精英"]
missing_topics = ["pricing", "monetization"]
```

CollectorAgent 可生成：

```text
和平精英 官网 充值 付费 道具
和平精英 商业模式 皮肤 赛季通行证
和平精英 monetization in-app purchase revenue
```

### 中优先级：AnalystAgent 支持字段级返工

AnalystAgent 应该根据 QA 指令只修复失败字段，例如：

- `ProductProfile.positioning`
- `FeatureTree.core_features`
- `PricingModel.tiers`
- `UserPersona.goals`

这样可以减少重复分析，也能让 Trace 更清楚地展示“修复了什么”。

### 中优先级：ReportWriterAgent 支持 Claim 级返工

ReportWriterAgent 应该根据 QA 指令修复：

- 缺少 evidence_ids 的 Claim
- 缺少某竞品 Claim
- Claim 与 Evidence 竞品不匹配
- Markdown 格式不合格

Prompt 中可以加入：

```text
You are rewriting only the failed claims.
Do not modify passed claims unless necessary.
Use only evidence_ids from the same competitor.
```

### 中优先级：前端展示 ReworkContext

QA Panel 可以新增：

- 缺失竞品
- 缺失主题
- 失败 Claim
- 建议 query
- 实际返工目标 Agent

Trace Viewer 可以展示每轮 Agent 是否使用了 `ReworkContext`。

### 低优先级：返工效果评估指标

可以增加：

- `before_rework_error_count`
- `after_rework_error_count`
- `new_evidence_count`
- `fixed_claim_count`
- `remaining_risk_count`

用于说明自动返工是否真的改善了结果。

## 建议下一步开发顺序

1. 新增 `ReworkContext` Schema。
2. QaAgent 在失败时生成结构化 `ReworkContext`。
3. Runner 在 auto_rework 时把 `ReworkContext` 传给目标 Agent。
4. CollectorAgent 优先支持 `missing_competitors + missing_topics + suggested_queries`。
5. ReportWriterAgent 支持 `missing_claim_competitors + mismatched_evidence_claims`。
6. AnalystAgent 支持字段级返工。
7. 前端 QA Panel 和 Trace Viewer 展示 ReworkContext。

## 结论

当前自动返工流程已经可以作为 Demo 展示多 Agent QA 闭环，但它的返工粒度仍偏粗。下一阶段应把 QA 的自然语言错误说明升级为结构化 `ReworkContext`，让 Collector、Analyst 和 ReportWriter 能根据明确缺口执行定向修复，从而把“可能第二次成功”提升为“可解释、可复现、可追踪的自动修复”。
